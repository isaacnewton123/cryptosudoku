# 05 — Blockchain Layer (BOT Chain 677)

Unchanged chain choice; this doc pins **how the free-tier web stack talks to it**.

## 5.1 Contracts (UUPS, OpenZeppelin)

| Contract | Responsibility | Key methods (proposed) |
| -------- | -------------- | ---------------------- |
| Puzzle Registry | Pre-play commitment | `commitPuzzle(bytes32 hash, uint256 tournamentId)` |
| ZK Verifier | Proof check | `verifyProof(bytes proof, bytes32 commitment)` |
| Game Session | Score record | `recordScore(uint256 tournamentId, uint32 elapsedMs, bytes proof)` |
| Leaderboard | Ranking finality | `finalize(uint256 tournamentId)` |
| Reward Distributor | Top-100 payouts | `distribute(uint256 tournamentId)` |
| Staking | Revenue share | `stake/unstake/claim` |
| NFT Pass | Premium gating | `balanceOf/hasPass` |

All upgradeable via UUPS + 48h timelock + multisig (per `docs/03-product-architecture.md §3.3`). Testnet first: Bohr testnet (per roadmap Phase 0); mainnet Chain ID 677.

## 5.2 Frontend Wiring (App Only — Never Landing)

- `wagmi` + `viem`: `createConfig({ chains: [botChain677], connectors: [injected, walletConnect, coinbaseWallet] })`.
- `addresses.json` + `abis/*.json` generated by contract CI and copied into app (`src/contracts/`). Never hand-edit ABIs.
- Reads (commitment, rank, rewards) via public RPC (`VITE_RPC_URL`); writes via user wallet (user pays gas; no relayer on free tier).
- `submit-proof` Edge Function pre-validates (auth, window, commitment match) **before** prompting wallet signature — saves failed-tx UX + RPC calls.

## 5.3 Commit → Prove → Record → Payout Sequence

1. `generate-puzzle` Edge Function → backend commits `solution_hash` on-chain (`commitPuzzle`) → stores tx in `puzzles.onchain_commitment`.
2. Player solves; WASM prover (client) builds proof against commitment (no grid revealed).
3. Wallet sends `recordScore` (via Verifier); `ScoreRecorded` event emitted.
4. `leaderboard-index` cron reads events → upserts `leaderboard_cache` → Realtime broadcast.
5. `close-epoch` → `finalize` → `distribute` (top-100) → indexer marks payouts; UI shows tx links.

## 5.4 Keys & RPC Discipline

- No deployer keys in Vercel/Netlify env. Deploys run from maintainer machine or CI with GitHub Secrets (out of scope for free-tier docs, but recorded here so nobody pastes keys into Netlify UI).
- Public RPC only in client env vars; rate-limit reads (cache commitments in Supabase row after first fetch).
- Explorer links configurable via `VITE_EXPLORER_URL`.
